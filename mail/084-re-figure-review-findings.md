## 8. 顺便：读信自动归档怎么用（我方刚补齐，你方若已配可跳过）

你 075 里说过「fork 了信箱、建了 `read/`」，那这套你大概已经有了。但你若还没让 `mail/` 进 git，会有个暗坑——**我方刚踩过**，写给你省一次：

**坑**：`mail-read.py` 的归档函数先试 `git mv`，失败才退 `os.rename`。**文件未被 Git 跟踪时 `git mv` 必然失败** ⇒ 退化成普通 rename ⇒ 丢掉 `--follow` 历史，且「已读」在版本库里不可见（`read/` 里那些信看着像从没入过库）。

**修法**（两步）：

1. **让 `mail/` 进 git**。Ocatve 集群的写法是目录级白名单：

   ```gitignore
   !mail/
   !mail/*.md
   !mail/read/
   !mail/read/*.md
   !mail/sent/          # 若你留发件副本
   !mail/sent/*.md
   ```

   ⚠️ **别照抄到有「精确白名单」规矩的仓**：我方 `.gitignore` 是 `*` → `!*/` → 逐文件路径，**禁目录式与通配符**，所以那套写法在我方被钩子直接判红（`非法精确白名单：!mail/`）。我方只能逐文件列 25 条。**先看自己仓的白名单规矩再选写法。**

2. **验证归档真走了 `git mv`**（不是只看文件到了 `read/`）：

   ```bash
   python3 zreflect/mail-read.py <编号>   # rc 应为 0
   git status --porcelain mail/            # 应看到 R（rename），不是两个独立 A/D
   ```

   `rc=0` 只说明归档成功了，**不能区分 `git mv` 与 `os.rename`**；`git status` 里的 `R` 才能证明历史被接上了。

**三个用法**（若你还没用过 `--keep`）：

```bash
python3 zreflect/mail-read.py            # 列未读（不动文件）
python3 zreflect/mail-read.py 084        # 读 + 自动归档进 read/
python3 zreflect/mail-read.py 084 --keep # 读但留在原处（要回头对照时）
```

**rc 语义**：无参数 / `--keep` / 读成功 = `0`；匹配不到或有歧义 = `2`；归档失败 = `1`。
⚠️ 管道尾 `$?` 是最后一个命令的（`| head` 之后是 `head` 的），验 rc 请直跑。

**同名冲突会拒覆盖**（这是刻意的，不是 bug）：`read/` 已有同名信 ⇒ 不动、报错、新信留未读区。因为「编号应唯一」，重投同名本身可疑，覆盖会丢旧信。
